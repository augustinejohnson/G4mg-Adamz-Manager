ReCloud ERP

The Operating System for Modern Teams

Project Handover & Full Historical Documentation

1. Executive Summary & Project Origins

ReCloud ERP is a comprehensive, multi-tenant Enterprise Resource Planning web application designed to be "The Operating System for Modern Teams." The project development escalated significantly starting from early July 2026, transitioning from a basic retail application into a massive, multi-industry platform covering Law Firms, General Retail, B2B, HR, CRM, POS, Accounting, and more.

The application is built to be scalable, fast, and visually appealing, utilizing modern web technologies and a serverless architecture to ensure high availability and low maintenance overhead. Strict Role-Based Access Control (RBAC) and Subscription Tier logic (Basic vs Premium) were heavily emphasized throughout development to create a commercial-ready SaaS product.

Architecture Overview

The system utilizes a Multi-Tenant Single Page Application (SPA) architecture:

  • Multi-Tenancy & Industry Segregation: Organizations are strictly isolated. A currentTenant ID is injected into every module. Furthermore, industry logic (e.g., Law Firm vs Retail) conditionally hides or shows modules to ensure UI relevance (e.g., Law firms don't see POS or B2B features).
  • Component-Based Structure: Features are divided into isolated standalone modules (e.g., PosModule.jsx, CrmModule.jsx, AccountingModule.jsx, LawModule.jsx) orchestrated by a central Hub in App.jsx.
  • Super Admin Control: A global backend portal allowing the platform owner to manage tenant subscriptions (Basic/Premium), revoke access, and set global API keys (e.g., Paystack Live keys).
  • API & Webhooks: Built to communicate with external apps. Tenants can generate API keys to allow third-party apps to securely read/write to their specific database slice.

3. Detailed Feature Breakdown (Module by Module)

A. Point of Sale (POS) Module

  • Cart & Checkout: Fast item scanning, quantity adjustments, tax calculations. Split payments (Cash, Card, Transfer). Integration with Paystack.
  • Smart Internet Lookup: Integrated OpenFoodFacts API to auto-fill product data upon scanning barcodes.
  • Shift Management: Cashiers open shifts with a cash float and close shifts with a Z-Report, balancing expected cash vs actual cash.
  • Live Inventory Deduction: Checking out immediately deducts stock globally and locally, fixing an earlier issue where stock deductions were delayed.
  • Receipt Generation & Hardware Support: Prints to both A4 and 80mm thermal receipt printers.
  • Recent Sales History: A modal allowing users to view recent transactions. Strict RBAC ensures only Admin users can void/delete past sales to prevent cashier embezzlement. Voiding also reverses the accounting ledger automatically.

B. Accounting Module

  • Double-Entry Ledger: Core journal and ledger tracking all organizational finances.
  • Financial Reports: Automated generation of Trial Balances, Profit & Loss (P&L) statements, and Balance Sheets. Added robust PDF and CSV export functionalities.
  • Automated Integrations: POS checkouts automatically push localized records to the ledger. We tagged POS entries with source: 'pos' to ensure the accounting engine properly aggregates revenue without double-counting the raw POS sales and the ledger entries simultaneously.

C. CRM Module

  • Customer Directory & Activity Logs: Clicking a customer reveals a sliding drawer with full contact info and activity logs.
  • Integrated Communications: Added functionality to send direct emails to customers (via EmailJS/Zoho integration) and direct WhatsApp message links. Added a Note-taking feature.
  • Pipelines & Invoicing: Pipeline deal tracking and integrated invoicing tools linking directly back to the Accounting AR trackers.

D. Discuss Module (Internal Comms)

  • Public Channels: Slack-style public channels. Admins can dynamically add or remove employees from channels.
  • Direct Messages (DMs): Private 1-on-1 messaging between employees using deterministic channel IDs ([UserA_ID, UserB_ID].sort().join('_')) to guarantee consistent message history across sessions.

E. HR Module

  • Employee Management: Employee directory, roles, and branch assignment.
  • Payroll Processing: Admins can set salaries. Payslips were upgraded into a detailed "Statement of Account" format including dates, additions, and deductions.
  • Payslip Archive: Added a calendar system to view and print historical payslips month by month.

F. Inventory Module

  • Stock Tracking: Real-time global and warehouse-specific stock tracking.
  • Product Imports: Fixed bugs relating to CSV imports to ensure bulk product uploads map correctly to the database schema.
  • Moves & Requisitions: Stock transfers between warehouses/branches.

G. Client Portal & Law Module

  • Client Access: Dedicated portal for clients to log in and view their invoices, deals, and documents.
  • Law Firm Specialization: Segregated workspace that hides retail-centric modules and focuses on Legal Contracts, Document Management, and Time-tracking.

4. Chronological Challenges & Solutions

July 2026 - Law Firm Segregation & API Setup

Challenge: The application initially showed retail features (Cost of Goods, POS, B2B) to Law Firm users, causing confusion. The user also wanted an API for external apps (like Odoo) to connect.

Solution: We implemented an 'Industry' flag during tenant registration. If a tenant is a 'Law Firm', the App.jsx conditionally hides all Retail-focused modules. We built a robust API Settings module generating secure API keys bound to specific tenants for secure external read/write access.

Late July 2026 - Authentication & Ghost Workspaces

Challenge: Users experienced "Ghost Workspaces" (deleted tenants still showing up on login) and "Insufficient Permissions" errors when trying to create clients or reset passwords.

Solution: Overhauled Firebase Authentication mappings. Ensured that when a tenant is deleted, all references in the central users collection are purged. Corrected Firestore Security rules to allow proper password resets and client portal creation.

Early August 2026 - UI Optimization & The Mobile Experience

Challenge: The application was described as "too big" and features were overlapping or cut off on smaller screens, specifically in the Inventory templates and POS.

Solution: Implemented a massive UI overhaul across all modules, reducing padding/margins, utilizing two-layer layouts for the Inventory visual hierarchy, and ensuring responsive design for mobile point-of-sale functionality.

August 11-12, 2026 - Email Notifications, Stock Sync & Subscriptions

Challenge: 1) Stock was not deducting globally in real-time when a POS sale was made. 2) EmailJS configuration was failing to send notifications. 3) Basic and Premium plans were not enforcing feature limits.

Solution: 1) Updated the POS checkout function to run a bulk Firestore transaction to safely decrement stock levels. 2) Re-configured EmailJS with the correct Service ID, Template ID, and Public Key, resolving the Zoho/Gmail auth scopes. 3) Mapped out Subscription Tiers—Basic users are locked out of Accounting, B2B, Warehouses, and Discuss modules, and limited in HR. Premium users gain full access.

August 12-13, 2026 - Accounting Double-Entry & Discuss DM Sync

Challenge: 1) Accounting Trial Balance was inflated because POS sales generated both raw sales documents and ledger array documents. 2) Direct Messages were broken because they were saved to one-sided channel IDs.

Solution: 1) Tagged POS entries with source: 'pos' and explicitly instructed the Accounting Module to filter out automated POS ledger entries from generic general ledger fetches. 2) Refactored DM channel IDs using a sorted array ([A, B].sort().join('_')) to ensure conversational parity.

August 13, 2026 - Security & POS Void Authorization

Challenge: Cashiers could potentially delete/void sales from the POS History.

Solution: Implemented conditional rendering (role === 'Admin') on the 'Void Sale' button inside the newly built Recent Sales modal. Voiding a sale was also programmed to purge the associated ledger entries to maintain accounting balance.

Mid-August 2026 - POS Architecture Overhaul, PWA Offline Mode, & AI Vendors

Challenge: 1) The PosModule.jsx file was over 1,100 lines long, making state updates slow and code hard to maintain. 2) The app lacked offline support for remote branches. 3) The AI Assistant was locked exclusively to OpenAI. 4) Mobile UX in the Discuss module suffered from keyboard layout shifts.

Solution: 1) Extracted POS logic into usePosStore.js (Zustand) and split the UI into dedicated components (PosProductGrid, PosCartSidebar, PosPaymentModal, PosShiftManager). 2) Converted the entire platform into a Progressive Web App (PWA) using Vite PWA Plugin and enabled Firestore multi-tab IndexedDB persistence for seamless offline work. 3) Refactored the AI module and Super Admin settings to dynamically support Anthropic, Gemini, Groq, and custom endpoints. 4) Fixed the mobile Discuss view by explicitly managing the chat container's scroll state (preventing `scrollIntoView` viewport shifts) and adding a prominent back button.

5. System Setup & Deployment Guide

Prerequisites

  • Node.js (v16+)
  • Git
  • Firebase CLI (npm install -g firebase-tools)

Local Development Setup

  1. Clone the repository: git clone https://github.com/augustinejohnson/recloud-erp.git
  2. Navigate into the project directory: cd erp-v2
  3. Install dependencies: npm install
  4. Run the development server: npm run dev

Production Deployment

Deployments are handled via the Firebase CLI to Firebase Hosting.

  1. Build the production bundle: npm run build
  2. Verify terminal logs for Vite/Esbuild syntax errors.
  3. Deploy to live server: npx firebase-tools deploy --only hosting

Live URL: https://recloud-erp.web.app
