Developer Pricing Guide

Internal framework for estimating costs, communicating value, and upselling feature progression.

1

Calculating "Cost of Production"

> The Value-Based Approach

Clients aren't paying for "lines of code"; they are paying for a business solution. Base your costs on Time, Complexity, and Value.

const cost = (Estimated_Hours * Hourly_Rate) + Complexity_Premium;

UI/UX Design

Visual layout, branding, and mobile responsiveness.

Frontend Logic

Coding, data fetching, and state management.

Backend/Security

Database schemas, routing, and data masking.

2

Project Progression & Upselling

Phase 1

Initial Delivery

Charge a fixed, one-time fee (e.g., ₦120,000). Ensure the client signs off that this specific "Scope of Work" is complete before taking on new features.

Phase 2

Maintenance

Offer a monthly Retainer (₦30k-₦50k/mo) covering bug fixes, minor text updates, and server monitoring.

If declined, explicitly state your hourly rate for ad-hoc fixes.

Phase 3

Feature "V2"

Treat major additions as entirely new projects with new scopes of work. Examples:

  • Full Checkout System
  • Customer Accounts
  • Automated Emails
3

Client Communication Rules

1. Never Code Before Approval

Always send the Invoice/Scope first. Let the client agree to the cost before you spend hours engineering.

2. Be Strict on Scope Creep

If asked to add a large unquoted feature, reply: "I can do that! It falls outside current scope, so I will send a separate estimate for Phase 2."

3. Highlight "Free" Value

If you throw in a small feature for free (e.g., WhatsApp button), make sure they know it. It builds massive goodwill.
